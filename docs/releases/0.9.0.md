# Open Data Products SDK 0.9.0 release notes

This release connects business documents to data product drafts, coding-assistant
handovers, Jira Cloud and OpenMetadata Data Marketplace workflows. Generated
products, plans and contracts are drafts requiring domain review.

## CLI experience and setup

- Use `open-data-products config setup` to configure LLM providers, models,
  credentials, OpenMetadata, Jira and optional organization details. Inspect
  settings with `config show` and test configured services with `config test`.
  The LLM check sends a short prompt and may incur provider cost.
- Configure organization details as a default ODPS `dataHolder`. Existing
  conflicting holder values are preserved and reported for review.
- Handover preparation and Jira delivery default to interactive human mode.
  Specify `--mode agent` for non-interactive execution with JSON results.
  Agent mode sends business content and selected evidence to the configured LLM
  provider and creates Jira issues without interactive confirmation.
- The top-level `handoff` and `integrations` commands have been removed. Use
  `handover` for preparation and `openmetadata api` for advanced platform
  operations; update existing scripts accordingly.

## Coding-assistant handover and Jira

- Prepare an OpenSpec-based change package for a business document or folder.
  Packages contain an enriched ODPS draft, a separate ODCS draft, field mappings,
  a proposed output schema where supported, planning artifacts and open questions.
- Deliver packages and their supporting documents to Jira Cloud using the reusable
  Jira adapter. Batch results and local journals report completed, partial and
  unknown outcomes; ambiguous writes must be inspected before retrying.
- MCP exposes classified review and execution tools for business-to-handover
  generation and Jira delivery. Its calls use reviewed digests and Jira journals;
  MCP accepts existing metadata snapshots rather than running automatic discovery.
- `handover validate` uses the separately installed OpenSpec CLI for structural
  validation. OpenSpec CLI 2.2.0 was tested; the CLI is not required to install
  or use the rest of the SDK.

## OpenMetadata Data Marketplace

- Create data product entries in OpenMetadata's Data Marketplace from supported
  ODPS 4.1 drafts. A linked ODCS 3.1 contract can be imported and associated
  with the product. Product creation and contract import are separate operations;
  a failure can leave the product in place.
- The synthetic end-to-end benchmark verifies the associated contract and the
  integrity of its preserved ODCS source. The preserved product schema is not
  claimed to have been validated by OpenMetadata.
- Live testing used one OpenMetadata 2.1.0 installation. Product listing and
  search were checked for the configured account; marketplace UI visibility and
  access for other users were not established by the API checks.

## Metadata discovery

- Select an optional named metadata connection to discover candidate products,
  assets, schemas, contracts and lineage. OpenMetadata is the first implemented
  discovery adapter; other platforms require an adapter.
- Discovery is read-only and bounded. Candidate matches remain unverified,
  incomplete requests are reported, and the retained snapshot is limited to
  1 MiB. Handover evidence records source and platform references without
  including credentials.

## Validation and boundaries

- Source size limits and targeted instruction-pattern screening apply to guided
  handover intake. They do not guarantee that every malicious input is detected.
- ODPS-to-ODCS alignment is not assessed without independent comparable schemas.
  Structural validation does not constitute business approval or implementation.
- The SDK supports Python 3.8.1 and later. See the [handover guide](../integrations/handoff.md),
  [OpenMetadata guide](../integrations/openmetadata.md), and [changelog](../../CHANGELOG.md)
  for detailed configuration, behavior and limits.
